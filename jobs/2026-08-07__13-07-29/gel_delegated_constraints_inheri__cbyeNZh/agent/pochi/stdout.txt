Records that break a rule must not sink the whole batch: they have to be rejected individually, classified by the rule they broke, and reported. The schema must contain exactly these object types, with exactly these pointer names: - `Region` — required `key: str`. `key` must be unique across all `Region` objects; the violation must report the message `REGION_KEY_DUPLICATE`. - abstract type `Revisioned` — required `revision: int64` whose minimum allowed value is `1`; the violation must report the message `REVISION_TOO_LOW`. - abstract type `Taggable` — a **multi** property `tags: str`; every individual tag value must satisfy the shared token rule (below) with a length limit of `12`. - abstract type `Asset`, which must extend **both** `Revisioned` and `Taggable`, with: - required `code: str` — must satisfy the shared token rule with a length limit of `16`, and must be unique **only among objects of the same concrete asset type**. The very same `code` value must remain insertable under a *different* concrete asset type. A same-type duplicate must report the message `CODE_DUPLICATE_IN_KIND`. - required `serial: str` — must be unique **across the whole `Asset` hierarchy**, i.e. a value used by one concrete asset type must be rejected for every other concrete asset type too. The violation must report the message `SERIAL_DUPLICATE_GLOBAL`. - required single link `region` pointing at `Region`. - required `slot: int64`, required `capacity: int64`, required `reserved: int64`. - the pair (`region`, `slot`) must be unique **only among objects of the same concrete asset type**; the same (`region`, `slot`) pair must remain insertable under a different concrete asset type. The violation must report the message `SLOT_DUPLICATE_IN_KIND`. - `reserved` must never be greater than `capacity`; the violation must report the message `CAPACITY_EXCEEDED`. - `ServerAsset`, extending `Asset` — required `hostname: str`. - `StorageAsset`, extending `Asset` — required `volume_gb: int64`. - `Operator` — required `name: str`, unique across all `Operator` objects, violation message `OPERATOR_NAME_DUPLICATE`; plus a **multi** link `crew` pointing at `Asset` that carries a link property `role: str`. A single `Operator` must never be linked to two assets carrying the same `role` value (two *different* `Operator` objects may each use the same `role`). The violation must report the message `ROLE_DUPLICATE_FOR_OPERATOR`. The **shared token rule** must be expressed as exactly one user-defined *abstract* constraint in module `default` that accepts a single `int64` parameter and is reused at both sites (`Asset.code` with `16`, `Taggable.tags` with `12`). No other user-defined abstract constraint may exist in module `default`. A value satisfies the rule when it matches the regular expression `^[A-Z][A-Z0-9_]*$` **and** its length is less than or equal to the parameter. A violation must report the message `TOKEN_INVALID(max=16)` for `code` and `TOKEN_INVALID(max=12)` for `tags`.
